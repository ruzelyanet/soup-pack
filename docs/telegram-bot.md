# SoupPack — Telegram-бот магазина

Бот, через который клиент смотрит каталог, собирает корзину и оформляет доставку прямо в Telegram.
Заказы попадают в общий список заказов админки с источником **`telegram`** (в интерфейсе — «через Telegram»).

Бот работает **внутри процесса Strapi** (`backend/`): отдельный сервис запускать не нужно.
Включается и настраивается **в админке** («SLA и Telegram») — это тот же бот, что присылает
сотрудникам уведомления о заявках.
Данные читаются напрямую из Strapi, а заказ создаётся тем же сервисом, что и заказы с сайта
(`api::order.order.buildAndCreate`), поэтому цены, скидки, клиенты, история заказа и уведомления
в админке работают так же, как для сайта.

---

## 1. Что видит клиент

### Первый экран (`/start`)

1. Приветствие — из поля «Приветствие на первом экране» в админке (если пусто — текст по умолчанию).
2. Телефон магазина и часы работы — из single-type **«Контакты магазина»** (админка → «Контакты»).
3. Кнопки категорий (по две в ряд) и кнопка «🛒 Корзина».
4. Внизу появляется постоянное меню: **📂 Категории · 🛒 Корзина · 📞 Телефон**.
   Те же пункты есть в синей кнопке «Меню» слева от поля ввода: `/catalog`, `/cart`, `/phone`, `/start`.

### Каталог категории

- Товары приходят **по 5 штук**. Каждый — отдельное сообщение: **фото, название, вес, цена, состав**.
  Если состава нет, показывается описание. Если цена со скидкой — старая зачёркнута.
- Под товаром — кнопка **«➕ Добавить в корзину»**. После первого нажатия она превращается в
  **`➖` · `🛒 N шт` · `➕ Ещё`**: можно добавить ещё, убавить или перейти в корзину.
- После пятёрки — сообщение «Показано 5 из 12» с кнопкой **«⬇ Ещё (7)»**. По нажатию кнопка
  с прошлого сообщения убирается и приходят следующие 5. На последней странице — «Это все товары в …».
- Пустые категории (без опубликованных товаров в продаже) в списке не показываются.

### Корзина

- Список позиций: `Название — 2 × 55 000 сум = 110 000 сум`, при наличии скидки — сумма, скидка и итог.
- У каждой строки кнопки `➖` / `➕` / `✖`; внизу **«🧹 Очистить»**, **«✅ Оформить заказ»**,
  «📂 Продолжить покупки». Сообщение корзины обновляется на месте.
- Цены и скидки считаются движком `api::price.pricing` с источником `telegram` — так же, как сайт.
- Если товар сняли с продажи (или у него пропала цена), он автоматически убирается из корзины,
  а клиент видит предупреждение.

### Оформление заказа (форма по стандарту)

| Шаг | Что спрашиваем | Как принимаем | Проверка |
|---|---|---|---|
| 1 | **Имя** | текстом; если клиент уже заказывал — кнопка с прошлым именем | 2–60 символов |
| 2 | **Номер телефона** | кнопка «📱 Отправить мой номер» (контакт Telegram) или текстом | только узбекский номер, приводится к `+998XXXXXXXXX` |
| 3 | **Адрес доставки** | текстом: улица, дом, квартира — **или** геопозиция: кнопка «📍 Отправить геопозицию» (с телефона), 📎 → Геопозиция, ссылка на точку из Google Карт / Яндекс Карт / 2ГИС / OSM / Apple Maps, координаты `41.311, 69.279` | адрес текстом 5–200 символов; геопозиция **необязательна** |
| 3а | **Уточнение адреса** — только если прислали точку | текстом: дом, квартира, подъезд | 2–200 символов |
| 4 | **Подтверждение** | сводка: имя, телефон, адрес, состав, итог | кнопки «✅ Подтвердить», «✏️ Изменить данные», «✖ Отмена» |

- **Геопозиция необязательна.** Если клиент написал только адрес, заказ создаётся без координат,
  в карточке заказа в админке появляется пометка «Точка на карте не указана» — оператор уточняет
  у клиента и ставит точку через «Редактировать» (пока заказ в статусе «Новый»).
- **С компьютера** Telegram Desktop, macOS и Web не умеют отправлять геопозицию кнопкой — поэтому принимаем и ссылку на карту. Разбор ссылок — `backend/src/bot/geo.ts`;
  короткие ссылки (`maps.app.goo.gl`, `yandex.uz/maps/-/…`, `go.2gis.com`) сервер раскрывает по редиректу,
  поэтому ему нужен доступ к этим сайтам.
- Подсказка в поле ввода одна на всех клавиатурах — «Напишите сообщение…». Подсказки под каждый шаг
  не используем: приложения Telegram (замечено на macOS/Desktop) обновляют подсказку с опозданием, и она
  показывалась не на своём шаге. Что вводить, бот пишет в самом сообщении шага.
- В подтверждении есть ссылка «Точка на карте» — можно проверить, куда поедет курьер.
- На любом шаге есть кнопка **«✖ Отменить оформление»**; команды и кнопки меню тоже прерывают
  оформление. Корзина при этом сохраняется.
- Повторное нажатие «Подтвердить» второй заказ не создаёт.
- После успеха: «✅ Заказ SP-123456-78 принят! … Мы позвоним на +998 …», корзина очищается.
  Имя, телефон и адрес запоминаются и предлагаются кнопками в следующий раз.
- При ошибке сервера клиент видит телефон магазина и кнопку «🔁 Повторить».

## 2. Что попадает в заказ

| Поле заказа | Значение |
|---|---|
| `source` | **`telegram`** |
| `status` | `new` |
| `client` | найден или создан по телефону (`+998…`); имя, адрес и координаты обновляются |
| `address` | текст из шага 4 |
| `lat`, `lng` | точка из шага 3, если клиент её прислал; иначе пусто |
| `items`, `subtotal`, `discountTotal`, `total` | расчёт `pricing.quote` (источник `telegram`) |
| `paymentMethod` | `cash` — оплата при получении |
| `deliveryMethod` | `courier_now` |
| `comment` | `Telegram: Имя @username (chat 123456789)` — чтобы сотрудник мог найти клиента в Telegram |

Заказ проходит обычный путь: событие `created` в истории («Заказ создан через Telegram»), всплывающее
уведомление о новом заказе в админке в реальном времени, дальше — «взять в работу», оплата и т. д.

## 3. Запуск

### 3.1. Бот

Если бот для уведомлений о заявках уже заведён — **используется он же**, новый создавать не нужно.
Иначе: **@BotFather** → `/newbot` → имя и username → токен вида `123456789:AA…`.
По желанию там же: `/setuserpic` (аватар), `/setdescription` (текст до нажатия «Старт»).
Список команд меню бот выставляет сам.

### 3.2. Включить в админке

Админка → **«SLA и Telegram»** (только роль «главный»):

1. Карточка **«Telegram»** → поле **Bot token** (если уже «установлен» — ничего не трогать).
2. Карточка **«Магазин в Telegram»** — галочка **«Включить магазин в боте для клиентов»** включена
   по умолчанию: если токен уже был сохранён, бот запускается сам при старте сервера. При желании задайте **текст приветствия**.
3. **«Сохранить»**.

Бот запускается сразу, перезапуск сервера не нужен. Под формой видно состояние:

| Состояние | Что значит |
|---|---|
| 🟢 **Работает · @имя_бота** | всё в порядке, ссылка открывает бота |
| 🟡 Запускается… | идёт подключение к Telegram |
| 🔴 Telegram не принял токен | неверный Bot token |
| 🔴 Этот токен уже опрашивает другой сервер (409) | бот с этим токеном запущен ещё где-то (см. раздел 5) |
| ⚪ Выключен / не указан Bot token | галочка снята или токена нет |

В логе сервера бот всегда пишет, что с ним: `[shop-bot] запущен как @… — откройте https://t.me/…`,
`[shop-bot] выключен: <причина>` или `[shop-bot] не удалось подключиться (попытка N): <ошибка> — повтор через 10 с`.
Если сети до Telegram нет, бот повторяет подключение каждые 10 секунд; при неверном токене — ждёт исправления в админке.

Что происходит при сохранении:

- сменили только приветствие — применяется на лету, бот не перезапускается;
- сменили токен — бот переподключается с новым;
- сняли галочку — бот перестаёт отвечать клиентам (уведомления сотрудникам работают по своим галочкам, независимо);
- после ошибки повторное «Сохранить» пробует подключиться снова.

Уведомления сотрудникам и магазин включаются **отдельно**: можно оставить только уведомления, только магазин или оба.

### 3.3. Что ещё заполнить в админке

- **Контакты магазина** — телефон и часы работы (показываются на первом экране и по «📞 Телефон»;
  если телефон узбекский, бот дополнительно присылает карточку контакта, по которой можно позвонить).
- **Категории** и **продукты** — опубликованные, с флагом «в продаже», с ценой. Фото берётся из поля `image`,
  состав — из `composition`.

### 3.4. Переменные окружения (необязательно)

В `.env` для бота ничего прописывать не нужно. Есть две служебные переменные:

| Переменная | Назначение |
|---|---|
| `TELEGRAM_SHOP_BOT_ENABLED=false` | не запускать бота **на этой машине**, даже если он включён в настройках. Нужна, когда локально работаете с копией боевой базы: иначе локальный сервер и боевой начнут опрашивать один токен (ошибка 409) |
| `TELEGRAM_SHOP_API_ROOT` | другой адрес Bot API — локальный `telegram-bot-api` или прокси, если `api.telegram.org` недоступен с сервера |

Где хранятся настройки: single-type `request-setting`, поля `telegramBotToken` (приватное, в API не отдаётся),
`shopBotEnabled`, `shopBotGreeting`. Ответ `GET /staff/request-settings` дополнительно содержит
`shopBot: { state, username, error, reason }` — текущее состояние бота.

## 4. Устройство

```
backend/src/bot/
├── index.ts     запуск/перезапуск по настройкам (syncShopBot), long polling, статус для админки
├── bot.ts       сценарии: приветствие, каталог, корзина, оформление (класс ShopBot)
├── catalog.ts   доступ к данным Strapi: категории, товары, цены, корзина, создание заказа
├── session.ts   хранение корзины и шага оформления (DbSessionStore / MemorySessionStore для тестов)
├── texts.ts     чистые функции: тексты, форматирование цен/телефонов, операции с корзиной
└── api.ts       тонкий клиент Bot API на встроенном fetch (без npm-зависимостей)

backend/src/api/telegram-session/   content-type «Сессия Telegram-бота» (без публичных маршрутов)
backend/tests/telegram-bot.test.ts  тесты texts.ts и сценариев ShopBot на фейковом Telegram
```

### Сессии

Таблица `telegram_sessions`, одна строка на чат: `chatId`, `username`, `firstName`, `cart`, `step`,
`form` (данные текущего оформления), `profile` (имя/телефон/адрес с прошлого заказа), `lastOrderCode`.
Корзина и незавершённое оформление переживают перезапуск сервера. Сессии видны в стандартной админке
Strapi (`/admin` → Content Manager → «Сессия Telegram-бота») — удобно для отладки.

### Корзина хранит `documentId`

В Strapi 5 при каждой повторной публикации товара у опубликованной версии меняется числовой `id`.
Поэтому корзина и кнопки хранят **`documentId`**, а числовой id текущей опубликованной версии
подставляется в момент расчёта/создания заказа. Отредактировали товар в админке — у клиентов в корзине он остаётся.

### Кнопки (`callback_data`)

| Данные | Действие |
|---|---|
| `cats` | список категорий |
| `cat:<categoryDocumentId>:<offset>` | страница товаров категории (по 5) |
| `add:<productDocumentId>` / `dec:<…>` | +1 / −1 из карточки товара |
| `cart` | открыть корзину |
| `ci:` / `cd:` / `cr:<productDocumentId>`, `cclr` | +1 / −1 / убрать строку / очистить — из корзины |
| `chk` | начать оформление |
| `ok` / `chg` / `no` | подтвердить / изменить данные / отменить |

### Фото

Если файл лежит в `public/uploads` (локальный провайдер загрузки), бот загружает его в Telegram
multipart-запросом — это работает и на локальной машине, где Telegram не может скачать картинку по URL.
Берётся формат `medium` (≈750 px), затем `small`, затем оригинал. Если провайдер внешний (S3, Cloudinary)
и URL абсолютный — передаётся ссылка. После первой отправки бот запоминает `file_id` и повторно файл не грузит.
Если фото отправить не удалось — товар показывается текстом.

## 5. Эксплуатация и ограничения

- **Один процесс на один токен.** Бот получает сообщения через `getUpdates` (long polling). Если запустить
  два экземпляра backend с одним токеном (например, локально и на сервере), Telegram отвечает `409 Conflict` —
  в логе `polling error … 409`. Для локальной разработки заведите отдельного тестового бота
  или выключите локальный через `TELEGRAM_SHOP_BOT_ENABLED=false`.
- При старте бот снимает вебхук (`deleteWebhook`), так как с вебхуком polling не работает.
- Магазин и уведомления сотрудникам работают через один токен: отправка уведомлений не мешает polling.
  Сотрудники, указанные в Chat IDs, тоже могут открыть бота как клиенты — это не мешает уведомлениям.
- Апдейты обрабатываются последовательно — порядок нажатий одного клиента сохраняется. Для магазина такого
  масштаба этого достаточно.
- **Скидки по источнику.** Если у скидки в `conditions.sources` перечислены источники, Telegram-заказы
  получают её только при наличии там `"telegram"`. Скидки без условия по источнику действуют как обычно.
- Наборы (`order-set`) в боте пока не продаются — только отдельные товары.
- Клиент не получает в Telegram уведомлений о смене статуса заказа (см. раздел 7).

## 6. Тесты

```bash
cd backend
npm test            # все тесты, в т. ч. tests/telegram-bot.test.ts
```

`telegram-bot.test.ts` покрывает: форматирование цен и телефонов, операции с корзиной, первый экран,
пагинацию по 5, «Добавить → Ещё», полный сценарий оформления (с геопозицией, ссылкой на карту и только адресом текстом; защиту
от двойного подтверждения), отмену оформления кнопкой меню, пустую корзину.

Дополнительно при разработке сценарий прогонялся на настоящем Strapi (SQLite + seed-каталог):
каталог, корзина с перепубликацией товара, создание заказа с `source = telegram`, а также
транспорт (polling, меню команд, multipart-фото) на локальном фейковом сервере Bot API.

## 8. Идеи для следующего шага

- **Статусы заказа клиенту в Telegram**: сохранять `chatId` в заказе (поле или связь с `telegram-session`)
  и в `logEvent` при `status_changed` отправлять клиенту «Заказ принят / в пути / доставлен».
- Наборы из «Конструктора заказов» отдельной категорией.
- Выбор способа оплаты и предзаказа на время (поля в заказе уже есть).
- Webhook вместо polling для продакшна с несколькими инстансами backend.
- Вынести карточку «Магазин в Telegram» в отдельный пункт меню, если настроек станет больше.
