# SoupPack — Карточка скидки и форма создания/редактирования

Техническое задание для Claude Code. Разделяем просмотр и редактирование скидки: отдельная **карточка скидки** (просмотр, статус, действия, превью «как увидит клиент», статистика, история) и отдельная **страница создания/редактирования** с понятной формой.

> Перед началом прочитай этот файл целиком, затем `docs/pricing-and-discounts.md` (модель скидок, версионирование, движок) и текущий код из раздела 1. Если код расходится с описанием — ориентируйся на код и отметь расхождение в итоговом отчёте.
>
> Сначала покажи план и список файлов к изменению — и жди подтверждения.

---

## 0. Ключевые принципы

1. **Просмотр ≠ редактирование.** Клик по скидке в списке открывает карточку (только чтение). Редактирование — отдельная страница, куда попадаем кнопкой «Редактировать».
2. **Статус меняется только кнопками в карточке**, не полем формы. Каждая смена статуса — отдельный запрос `POST /staff/discounts/:id/status`, проверяется на сервере и пишется в историю.
3. **Новая скидка всегда создаётся черновиком.** Клиенты её не видят, пока менеджер не нажмёт «Активировать» в карточке.
4. **Превью считает сервер.** Цифры в блоке «Как увидит клиент» приходят из движка (`evaluate`), админка не дублирует формулы скидок.
5. **Каждый блок формы объясняет себя:** заголовок, одна-две строки «за что отвечает» и пример. Менеджер не должен знать слова `line`, `exclusiveGroup`, `stackable`.
6. **Логику расчёта скидок не меняем.** Порядок уровней, приоритеты, округления, распределение — как есть.

### 1.1. Проблемы, которые закрывает задача

1. **Статус можно выставить из формы как угодно.** `staffCreate` берёт `body.status` — можно сразу создать активную скидку. `staffUpdate` тоже принимает `status`.
2. **`staffSetStatus` не проверяет переходы.** Архивную скидку можно вернуть в `active`; можно активировать скидку на товары без единого товара (она молча ни к чему не применяется).
3. **Версионирование включает скидку.** При создании новой версии в `staffUpdate` стоит `status: body.status || 'active'` — если статус не передан, отредактированная скидка на паузе становится активной. Новая версия должна наследовать статус предыдущей.
4. **Нет истории** — неизвестно, кто и когда поставил на паузу или активировал.
5. **Форма непонятна:** технические термины («Строка», «Эксклюзивная группа», «Сочетается с другими скидками того же уровня»), важные поля спрятаны по табам, цели задаются строками «тип + значение», нет подсказок, что и где увидит клиент.
6. **Вкладка «Проверка» не видит черновик:** `simulate` берёт только активные скидки, поэтому проверить расчёт до активации нельзя.

## 3. Жизненный цикл статуса

### 3.1. Переходы

| Из \ В | `active` | `paused` | `archived` | удалить |
|---|---|---|---|---|
| `draft` | «Активировать» | — | «В архив» | «Удалить черновик» (только если нет применений) |
| `active` | — | «Поставить на паузу» | «В архив» | — |
| `paused` | «Возобновить» | — | «В архив» | — |
| `archived` | — | — | — | — |

Любой другой переход → `400 INVALID_STATUS_TRANSITION`. Архив — конечное состояние, только просмотр (и «Создать копию», см. 5.6).

### 3.2. Проверки при активации и возобновлении

Сервер перед переходом в `active` проверяет готовность. При ошибке — `400 DISCOUNT_NOT_READY`, `details.problems: Array<{ field, code, message }>`:

| Проверка | `code` | Сообщение |
|---|---|---|
| `name` не пустое | `NAME_REQUIRED` | Укажите название |
| `percent`: `benefitValue` 1–99; `fixed_amount`/`fixed_price`: > 0 | `BENEFIT_INVALID` | Неверный размер скидки |
| `level = line`: есть хотя бы одна цель без `exclude` | `TARGETS_REQUIRED` | Выберите товары или категории |
| `level = set`: есть хотя бы один набор | `TARGETS_REQUIRED` | Выберите набор |
| `endsAt` задан → `endsAt > now` | `ALREADY_ENDED` | Дата окончания уже прошла |
| `startsAt` и `endsAt` заданы → `startsAt < endsAt` | `PERIOD_INVALID` | Начало позже окончания |
| `timeFrom`/`timeTo` — валидные `HH:MM` | `TIME_INVALID` | Неверное время |

Те же проверки (без `ALREADY_ENDED`) отдаются в `staffFindOne` как `_readiness: { ready: boolean, problems: [...] }` — карточка черновика показывает чек-лист до нажатия кнопки.

### 3.3. Отображаемое состояние (вычисляется, в БД не хранится)

| `status` | Условие | Чип | Цвет |
|---|---|---|---|
| `draft` | — | Черновик | серый |
| `active` | `startsAt > now` | Запланирована | синий/olive |
| `active` | период идёт | Активна | зелёный |
| `active` | `endsAt ≤ now` | Завершилась | серый с обводкой |
| `paused` | — | На паузе | saffron |
| `archived` | — | В архиве | светло-серый |

Вычислять одной функцией `displayState(d, now)` в `admin/src/utils/discount.ts` (см. 6.4) и использовать в списке, карточке и форме. Сервер дополнительно отдаёт `_displayState` в `staffFindOne` и `staffList`, чтобы фильтр по «Запланирована/Завершилась» работал без расхождений с часами браузера.

## 4. Бэкенд

### 4.1. `staffCreate`

- `status` из тела **игнорировать**, всегда `draft`.
- Остальная валидация — как сейчас.
- Записать событие `created` (4.4).

### 4.2. `staffUpdate`

- Поле `status` в теле → `400 STATUS_NOT_EDITABLE` («Статус меняется кнопками в карточке»).
- При создании новой версии: `status` новой записи = `existing.status` (а не `'active'`). Старая уходит в `archived`, как сейчас.
- Записать событие `updated` (с списком изменённых полей) или `version_created` (`fromId`, `toId`, `version`).
- Ответ дополнить `{ versionCreated: boolean }`, чтобы форма показала понятный toast.

### 4.3. `staffSetStatus`

- Проверять матрицу 3.1 и готовность 3.2.
- Принимать необязательный `comment` (например, причина паузы).
- Записать событие `status_changed` (`from`, `to`, `comment`).

Новый маршрут: `DELETE /staff/discounts/:id` — только `status = draft` и ноль записей в `order-discount`, иначе `400 CANNOT_DELETE`. Удаляет скидку, её цели и события.

### 4.4. История — content-type `discount-event`

По образцу `order-event` / `request-event`.

| Поле | Тип | Примечание |
|---|---|---|
| `discount` | relation manyToOne → `discount` | `inversedBy: events` |
| `type` | enum `created \| updated \| status_changed \| version_created \| duplicated` | |
| `fromStatus`, `toStatus` | string, nullable | для `status_changed` |
| `payload` | json | изменённые поля, id версий и т. п. |
| `comment` | string | |
| `employee` | relation manyToOne → `employee` | кто сделал |

`draftAndPublish: false`. События не редактируются и не удаляются (кроме удаления черновика целиком). При создании новой версии история предыдущей версии остаётся на ней; карточка показывает историю всей цепочки версий.

### 4.6. Превью — `POST /staff/discounts/preview`

Считает, как будет выглядеть скидка у клиента. Работает и для **сохранённой** скидки (карточка), и для **несохранённой формы** (редактор).

Запрос:

```ts
{
  discountId?: number,        // для карточки: взять скидку из БД
  draft?: DiscountPayload,    // для формы: то же тело, что в staffCreate (без сохранения)
  withActive?: boolean,       // default false: учесть другие активные скидки (кроме этой и её прошлых версий)
}
```

Ответ:

```ts
{
  placements: Array<'product_card' | 'discounts_page' | 'set_page' | 'cart' | 'checkout'>,
  products: Array<{ id, name, image, tint, basePrice, finalPrice, discountPercent, label, endsAt }>, // до 4 шт.
  sets: Array<{ id, name, banner, basePrice, finalPrice, discountPercent, label, endsAt }>,        // до 2 шт.
  checkout?: {                          // для level = order
    sampleBelow: { subtotal, hint: { missing, label } },     // корзина чуть ниже порога
    sampleAbove: { subtotal, discountTotal, total, percent }, // корзина, где скидка сработала
  },
  notes: Array<{ code: string, message: string }>,
}
```

Реализация:

- Собрать `DiscountSnapshot` из `draft` или из БД и вызвать **чистую `evaluate()`** из `pricing.ts`. Без `withActive` — только эта скидка; с `withActive` — плюс `loadActiveDiscounts()`, исключив эту скидку и её предыдущие версии.
- Момент расчёта `at = max(now, startsAt)`, чтобы превью запланированной скидки показывало результат.
- Контекст подобрать так, чтобы условия скидки выполнялись: `deliveryMethod` = первый из `conditions.deliveryMethods` (иначе `courier_now`), `paymentMethod` аналогично, время — внутри `timeFrom..timeTo`, день недели — первый из `weekdays`.
- Примеры товаров: для `line` — товары из целей; категории разворачиваются в их товары, `all-products` — первые по `sort`; исключённые не берём; до 4 шт. Для `set` — наборы из целей. Для `order` — две тестовые корзины из популярных товаров: чуть ниже `minSubtotal` и чуть выше.
- `notes` — **где клиент увидит скидку**, это главное для менеджера:

| Ситуация | `code` | Сообщение |
|---|---|---|
| `line` без условий | `SHOWN_IN_CATALOG` | Зачёркнутая цена и бейдж в каталоге, на странице товара и на странице «Скидки» |
| `line`/`set` с `minQty`, `minSubtotal`, `deliveryMethods`, `paymentMethods` | `CART_ONLY` | В каталоге цена без скидки — скидка появится в корзине при выполнении условий |
| есть `weekdays`/`timeFrom`/`timeTo` | `TIME_LIMITED` | В каталоге видна только в указанные дни и часы |
| `showInCatalog = false` | `HIDDEN` | Не показывается в каталоге и на странице «Скидки», но применяется в корзине |
| `level = order` | `CHECKOUT` | Видна на чекауте: «Ваша скидка −N%» и подсказка «добавьте ещё …» |
| с `withActive` у товара сработала другая скидка | `OVERRIDDEN` | На «{товар}» сейчас действует «{другая скидка}» — итог: … |

Сверь эти правила с `catalogPricing()` / `quote(source: 'catalog')` и клиентскими компонентами; если поведение другое — пиши в `notes` по факту кода и отметь в отчёте.

На ширине < `lg` — одна колонка: статус-баннер сразу под шапкой, затем hero, превью, детали, статистика, история.

### 5.2. Кнопки по статусу (шапка)

| Статус | Основная кнопка | Вторичные | В меню «⋯» |
|---|---|---|---|
| `draft` | **Активировать** (primary, disabled + tooltip, если `_readiness.ready = false`) | Редактировать | Создать копию · Удалить черновик · В архив |
| `active` | — | Редактировать · **Поставить на паузу** | Создать копию · В архив |
| `paused` | **Возобновить** (primary) | Редактировать | Создать копию · В архив |
| `archived` | — | — | Создать копию |

Подтверждения (PrimeVue `ConfirmDialog`, уже подключён в `App.vue`):

- **Активировать:** «Скидка начнёт действовать {сразу | с 10.11 в 00:00}. Клиенты увидят её {где — из `notes`}.»
- **Пауза:** «Клиенты перестанут получать скидку сразу. Уже оформленные заказы не изменятся.» + необязательное поле «Причина».
- **В архив:** «Это нельзя отменить. Скидка перестанет действовать и её нельзя будет редактировать — только создать копию.» Кнопка подтверждения — `danger`.
- **Удалить черновик:** «Черновик будет удалён без возможности восстановления.»

После любого действия — перезагрузить карточку, toast с результатом. Ошибку `DISCOUNT_NOT_READY` показать списком проблем в статус-баннере.

### 5.3. Hero

- Крупно: выгода (`−20%`, `−5 000 сум`, `Цена 25 000 сум`) — `font-display`, tomato.
- Под ней — **описание одной фразой**, генерирует `describeDiscount(d)` (6.4):
  «−20% на «Борщ» и категорию «Холодные супы», кроме «Окрошка»; по будням с 12:00 до 15:00; при доставке «Курьером сейчас»; с 10.11 по 20.11.»
- Публичная метка — отдельной строкой «Клиент видит: «…»» (или «Метка не задана — клиент увидит название»).

### 5.4. «Как увидит клиент» — превью

Данные — из `POST /staff/discounts/preview` (`discountId`). Переключатель «Только эта скидка / С учётом других активных» (`withActive`).

Блок выглядит как экран телефона: рамка шириной 390px со скруглением, фон клиента. Внутри — сегменты по `placements`:

- **Каталог** — 2–4 карточки товаров с зачёркнутой ценой, бейджем и датой «до …», как в клиентском `ProductCard`.
- **Страница «Скидки»** — плитка, как в `DiscountsPage.vue`.
- **Набор** — карточка набора со старой/новой ценой.
- **Чекаут** (для `order`) — блок «Ваша скидка −N%» и подсказка «Добавьте ещё 12 000 сум — скидка −10% на весь чек», как в `CheckoutPage.vue`; две корзины: ниже и выше порога.

Над рамкой — `notes` плашками-пояснениями (иконка + текст). Если `placements` пустой — пустое состояние «Клиент не увидит эту скидку в каталоге» + причина из `notes`.

Для черновика и паузы — полоса поверх рамки «Так будет выглядеть после активации».

### 5.5. Детали

Карточки-секции, у каждой заголовок и кнопка-карандаш «Изменить» (ведёт на `/discounts/:id/edit#<section>`; для архива скрыта):

- **Выгода** — тип простыми словами, значение, потолок «не больше N сум на заказ».
- **На что действует** — чипы товаров/категорий/наборов с миниатюрами и ссылками на их страницы в админке; исключения отдельной строкой «Кроме: …». Для чека — «На весь чек».
- **Условия** — список простыми словами или «Без условий — для всех заказов».
- **Период** — даты в `Asia/Tashkent`; «Бессрочно», если не задано; «Осталось 3 дня» для активной.
- **Сочетание с другими скидками** — приоритет, группа и сочетаемость — словами: «Если на товар действует несколько скидок из группы «cart-tier», применится самая выгодная для клиента».
- **Показ** — «Показывается в каталоге и на странице «Скидки»» / «Скрыта, применяется только в корзине».

### 5.6. Правая колонка

**Статус-баннер** (контекстный):
- `draft`: «Черновик — клиенты не видят эту скидку». Чек-лист `_readiness` (зелёные галочки/красные пункты со ссылкой на нужный раздел формы). Кнопка «Активировать» дублируется здесь.
- `active` + запланирована: «Начнёт действовать 10.11 в 00:00 (через 2 дня)».
- `active`: «Действует с … ». Если до `endsAt` < 3 дней — предупреждение «Заканчивается через N дн.».
- `active` + завершилась: «Период закончился {дата}. Скидка больше не применяется. Продлите период или отправьте в архив.»
- `paused`: «На паузе с {дата}, {кто}. Причина: …».
- `archived`: «В архиве — только просмотр».

**Статистика:** применений · заказов · сумма скидок · последнее применение. Если версий несколько — мини-таблица по версиям.

**История:** таймлайн `_events` (иконка по `type`, кто, когда, комментарий, для `updated` — какие поля). Список версий со ссылками на карточки прошлых версий; текущая выделена.

**Создать копию:** открывает `/discounts/new?copyFrom=:id` — форма заполнена копией (название + « (копия)»), статус — черновик, событие `duplicated` у исходной.

### 5.7. Проверить на тестовой корзине

Перенести вкладку «Проверка» из редактора в свёрнутый блок карточки. Вызывать `simulate` с `includeDiscountIds: [id]`, чтобы проверялись и черновики. Результат — построчно: базовая цена, применённые скидки, итог; «не применена — причина» переводить на русский (`minQty` → «не набрано минимальное количество» и т. д., словарь в `utils/discount.ts`).

## 6. Форма создания/редактирования — `pages/discounts/Editor.vue`

### 6.1. Каркас

Одна прокручиваемая страница **без табов** (табы прятали обязательные поля).

```
┌ AppTopbar: ← Новая скидка / Редактирование «…» ───────────────────────────┐
┌ Навигация (sticky) ┐ ┌ Форма: пронумерованные блоки ┐ ┌ Итог (sticky) ───────┐
│ 1 Название      ✓  │ │                               │ │ «−20% на Борщ …»      │
│ 2 Тип скидки    ✓  │ │                               │ │ мини-превью 1 карточки│
│ 3 Размер        !  │ │                               │ │ где увидит клиент     │
│ 4 На что        ·  │ │                               │ │ ошибки формы          │
│ …                  │ │                               │ │                       │
└────────────────────┘ └───────────────────────────────┘ └───────────────────────┘
┌ Нижняя sticky-панель: [Отмена]                       [Сохранить черновик] ┐
```

- Навигация — якоря на блоки, статус каждого: заполнен ✓ / ошибка ! / необязательный ·. На < `xl` скрывается.
- Правая колонка «Итог» — живое описание `describeDiscount(form)` и мини-превью одной карточки (`POST /staff/discounts/preview` с `draft`, debounce 400 мс). На < `lg` — сворачиваемая панель над нижней кнопкой.
- Нижняя панель: для новой скидки — «Сохранить черновик»; для существующей — «Сохранить». После создания → редирект в карточку `/discounts/:id` (там будет «Активировать»). После сохранения → в карточку.
- Хеш в URL (`#targets`) прокручивает к блоку — так работают кнопки «Изменить» из карточки.

### 6.2. Оформление блока

Каждый блок — белая карточка `rounded-2xl p-6`:

```
[2]  Тип скидки                                       ← номер в круге + font-display
     На что распространяется скидка: на отдельные      ← описание, text-ink-500, 1–2 строки
     товары, на готовый набор или на весь заказ.
     ─────────────────────────────────────────────
     поля блока
     💡 Пример: «−15% на обеды», «Набор недели за 99 000»  ← подсказка мелким, по желанию
```

Подписи полей — обычным регистром (не `uppercase tracking-wider`), с хинтом под полем. Ошибки — красным под конкретным полем, плюс прокрутка к первому блоку с ошибкой при сохранении.

### 6.3. Блоки

**1. Название и подпись для клиента**
- Описание: «Название видно только сотрудникам. Подпись — то, что увидит клиент на бейдже и странице «Скидки»».
- `name` (обязательно), placeholder «Борщ −20% ноябрь».
- `publicLabel`, placeholder «−20% на борщ до пятницы», счётчик символов (рекомендовано до 40), хинт «Если пусто — клиент увидит название».

**2. Тип скидки** (`level`)
- Описание: «На что распространяется скидка».
- Три крупные карточки-радио с иконкой, заголовком, одной строкой и «Где увидит клиент»:
  - **На товары** — «Скидка на отдельные товары или категории». Видно: в каталоге, на странице товара.
  - **На набор** — «Скидка на готовый набор целиком». Видно: на странице набора.
  - **На весь чек** — «Скидка на сумму заказа, обычно от порога». Видно: в корзине и на чекауте.
- Смена типа при заполненных целях → confirm «Выбранные товары/наборы будут сброшены».
- В режиме редактирования, если есть применения: плашка «Изменение типа создаст новую версию скидки».

**3. Размер скидки** (`benefitType`, `benefitValue`, `maxDiscountAmount`)
- Описание: «Сколько клиент экономит».
- Сегмент-кнопки с пояснением под каждой:
  - **Процент** — «−N% от цены»;
  - **Сумма** — «−N сум от цены» (для чека — «от суммы заказа»);
  - **Фиксированная цена** — «товар стоит ровно N сум» (скрыть для «На весь чек»).
- Поле значения с суффиксом `%` / `сум`, разделители разрядов. Валидация: процент 1–99, сумма > 0.
- Живой пример под полем на первом товаре из целей: «Борщ: 32 000 → **25 600 сум**». Для фиксированной цены выше базовой — предупреждение «Цена выше обычной — скидки не будет».
- «Ограничить скидку суммой» — переключатель, раскрывающий `maxDiscountAmount`; хинт «Например, −20%, но не больше 30 000 сум на заказ».

**4. На что действует** (скрыт для «На весь чек»; вместо него текст «Скидка действует на весь заказ — ограничения задаются в условиях»)
- Описание: «Выберите, к каким товарам применяется скидка. Можно сочетать товары и категории и исключить отдельные товары».
- Для «На товары»:
  - переключатель **«Все товары»** (→ `all-products`);
  - **Товары** — `MultiSelect` с поиском, в опции миниатюра, название, текущая цена;
  - **Категории** — `MultiSelect` с количеством товаров в каждой;
  - **Кроме товаров** — `MultiSelect` (→ цели с `exclude: true`), виден, если выбраны категории или «Все товары»;
  - итог: «Скидка будет действовать на 14 товаров» (раскрывающийся список).
- Для «На набор»: **Наборы** — `MultiSelect` с баннером и ценой набора.
- Преобразование в `targets[]` — в `utils/discount.ts` (`targetsToForm` / `formToTargets`), чтобы формат API не менялся.

**5. Условия** (`conditions`)
- Описание: «Когда скидка срабатывает. Без условий — для всех заказов в период действия».
- По умолчанию — текст «Без условий» и кнопка **«+ Добавить условие»** с меню. Каждое добавленное условие — строка с заголовком, полем, пояснением и крестиком «убрать»:
  - **Минимальная сумма заказа** — «Скидка сработает, если сумма заказа (после других скидок на товары) не меньше N сум». Для «На весь чек» показывать сразу, оно почти всегда нужно.
  - **Минимальное количество** (только «На товары») — «Нужно купить не меньше N шт. этого товара».
  - **Способ получения** — чипы «Курьером сейчас», «Предзаказ».
  - **Способ оплаты** — чипы.
  - **Дни недели** — 7 кнопок-переключателей Пн…Вс + быстрые «Будни» / «Выходные».
  - **Время** — два `DatePicker timeOnly` с … по …; хинт «По Ташкенту».
- Если добавлено условие, при котором скидка не видна в каталоге, — плашка из `notes` превью: «В каталоге цена будет без скидки — клиент увидит скидку в корзине».

**6. Период** (`startsAt`, `endsAt`)
- Описание: «Когда скидка действует. Время — по Ташкенту».
- Быстрые кнопки: «Бессрочно», «Сегодня», «7 дней», «До конца месяца», «Свои даты».
- Два `DatePicker` с временем. Валидация: начало < окончания; окончание не в прошлом.
- Подсказка: «Скидка с будущей датой после активации будет «Запланирована» и включится сама».

**7. Показ клиентам** (`showInCatalog`)
- Описание: «Показывать ли скидку как предложение».
- Переключатель «Показывать в каталоге и на странице «Скидки»», хинт: «Если выключено — бейджа и страницы не будет, но скидка всё равно применится в корзине (например, для скрытых скидок по способу оплаты)».

**8. Сочетание с другими скидками** — свёрнут по умолчанию («Дополнительно»)
- Описание: «Нужно, только если на один товар или чек может действовать несколько скидок одновременно».
- **Можно сочетать с другими скидками** (`stackable`) — «Если выключено, из подходящих скидок того же типа применится одна — самая выгодная для клиента».
- **Группа** (`exclusiveGroup`) — `Select` с существующими группами (собрать уникальные из списка скидок) + «Новая группа…». Хинт: «Из скидок одной группы клиент получит только одну, самую выгодную. Пример: пороги «−5% от 150 000», «−10% от 250 000» в группе «cart-tier»».
- **Порядок применения** (`priority`) — число, хинт «Меньше — раньше. Важен, только если скидки сочетаются».
- Пояснение мелко: «Скидки на товары, наборы и чек всегда применяются по очереди: сначала товары, потом наборы, потом чек».

### 6.4. `admin/src/utils/discount.ts` (новый)

Единственный источник текстов о скидке в админке:

## 11. Готово, когда

- [ ] Клик по скидке в списке открывает карточку; редактирование — только через кнопку «Редактировать».
- [ ] Новая скидка после сохранения попадает в карточку со статусом «Черновик» и кнопкой «Активировать».
- [ ] «Активировать» неготового черновика недоступна, в карточке виден чек-лист, что исправить; сервер тоже отклоняет (`DISCOUNT_NOT_READY`).
- [ ] Активная скидка → «Поставить на паузу» → «Возобновить» работает; клиентский каталог реагирует сразу.
- [ ] «В архив» спрашивает подтверждение; архивную скидку нельзя ни редактировать, ни активировать (ни из UI, ни через API).
- [ ] Редактирование скидки на паузе с применениями создаёт новую версию **на паузе**, а не активную.
- [ ] Статус нельзя поменять через `PATCH`.
- [ ] Каждое действие видно в истории карточки: что, кто, когда.
- [ ] Превью в карточке и форме показывает цены, совпадающие с клиентским каталогом/чекаутом для той же скидки (проверить на 3 скидках: товар без условий, товар с `minQty`, чек с порогом).
- [ ] Для скидки с условиями превью честно говорит, что в каталоге её не видно.
- [ ] Каждый блок формы имеет заголовок, описание и подсказки; в интерфейсе нет слов `line`, `stackable`, `exclusiveGroup`.
- [ ] Тесты проходят.
- [ ] Итоговый отчёт: что сделано, расхождения кода с этим ТЗ, что осталось.
